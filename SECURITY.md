# Security Policy

This document outlines the security policy for the Momo project, including
which versions receive security updates and how to report vulnerabilities.

## Supported Versions

Security updates are provided only for the latest release line. Older versions
are not patched and should be upgraded to a supported version.

| Version         | Supported          |
| --------------- | ------------------ |
| `v0.3.x-legacy` | :white_check_mark: |
| `v0.2.0-legacy` | :x:                |
| `v0.1.0-legacy` | :x:                |

## Reporting a Vulnerability

> **Do not open a public issue** for security vulnerabilities. A public issue
> discloses the vulnerability before a fix is available and puts users at risk.

Please report vulnerabilities privately using GitHub's **Private Vulnerability
Reporting** feature:

1. Open the repository's **Security** tab.
2. Click **Report a vulnerability** (under "Private vulnerability reporting").
3. Describe the issue in detail, including steps to reproduce, affected
   versions, and the potential impact.

### What to include

- A clear description of the vulnerability and its impact.
- Steps to reproduce, including any relevant code, configuration, or inputs.
- The affected version(s).
- Any suggested remediation, if available.

### What to expect

- We will acknowledge receipt within **5 business days**.
- We will keep you informed of progress and coordinate a fix and disclosure
  timeline with you.
- We request a reasonable embargo window before public disclosure, and we
  credit reporters in release notes unless you request otherwise.

## Security Advisories

Published security advisories are available under the repository's
**Security** tab > **Advisories**.
